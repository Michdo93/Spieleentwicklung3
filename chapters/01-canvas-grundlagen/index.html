Canvas-Grundlagen & Game-Loop

Der Ausgangspunkt für alles Weitere: ein <canvas>, sein 2D-Zeichenkontext, und die Schleife, die ein Standbild zu einem Spiel macht. Genau diese Loop-Struktur treibt später das komplette Ninja-Fight-Spiel an.

Das <canvas>-Element

Ein <canvas> ist erstmal nur eine leere Fläche fester Größe. Um darauf zu zeichnen, braucht man seinen 2D-Zeichenkontext — ein Objekt mit Methoden wie fillRect(), drawImage() oder arc(). 

<canvas id="stage" width="480" height="280"></canvas>

<script>
  const canvas = document.getElementById("stage");
  const ctx = canvas.getContext("2d");
  ctx.fillStyle = "#5fe0c9";
  ctx.fillRect(80, 120, 60, 60);
</script>

Das ist Demo 1: ein einziger Zeichenaufruf. Ohne irgendeinen Loop bleibt das Bild für immer so stehen — es "passiert" nichts mehr.

Der naive Loop: ein fester Schritt pro Frame

Um Bewegung zu erzeugen, muss man wiederholt zeichnen — requestAnimationFrame() ruft eine Funktion kurz vor dem nächsten Bildschirm-Refresh auf (meist 60× pro Sekunde). Der naheliegendste Ansatz: bei jedem Aufruf die Position um einen festen Betrag verschieben.

Naiv 
function frame() {
  x += 2; // fester Schritt
  draw(x);
  requestAnimationFrame(frame);
}
Das Problem 
// Bei 60fps: 120px/Sekunde
// Bei 30fps: nur 60px/Sekunde
// Bei 144fps: 288px/Sekunde
// -> Geschwindigkeit hängt vom
//    Bildschirm ab!

Das ist Demo 2 — funktioniert, aber die tatsächliche Geschwindigkeit hängt von der Bildwiederholrate des jeweiligen Geräts ab. Auf einem langsameren Rechner (oder einem Browser-Tab im Hintergrund) würde sich alles quälend langsam bewegen.

Der zeitbasierte Loop: die Lösung

requestAnimationFrame() übergibt der Callback-Funktion einen Zeitstempel. Die Differenz zum letzten Aufruf (dt, "delta time", in Sekunden) sagt genau, wie viel Zeit seit dem letzten Frame vergangen ist — Bewegung wird mit dieser Zeit skaliert statt mit einem festen Schritt. 

let lastTime = 0;

function loop(now) {
  if (lastTime === 0) lastTime = now;
  const dt = (now - lastTime) / 1000; // Sekunden
  lastTime = now;

  x += SPEED * dt; // SPEED in Pixel/Sekunde, nicht Pixel/Frame

  draw(x);
  requestAnimationFrame(loop);
}

Das ist exakt die Struktur, die GameManager.loop() in Ninja Fight verwendet (dort zusätzlich mit einer Obergrenze für dt, um bei sehr langen Pausen — z. B. einem Tab-Wechsel — keinen riesigen Sprung zu verursachen).

Zwischen den drei Demos wechseln und beobachten: Demo 1 steht still, Demo 2 bewegt sich (aber bildratenabhängig), Demo 3 zeigt den tatsächlichen dt-Wert jedes Frames an.
