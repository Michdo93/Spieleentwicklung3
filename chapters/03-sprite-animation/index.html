KAP·03

Sprite-Animation

Ein einzelner Frame ist nur eine Pose. Eine Animation ist nichts weiter als: mehrere Poses schnell genug nacheinander zeigen. Dieses Kapitel baut Schritt für Schritt die Logik auf, die drawNinja() in Ninja Fight tatsächlich verwendet.

Ein Sprite-Sheet ist eine Tabelle aus Posen

Das Helden-Sheet aus Kapitel 2 ist in Wirklichkeit ein Raster: 8 Spalten (Frames), 8 Zeilen (Zustände wie Idle, Walk, Jump, …). Jede Zelle ist 160×150 Pixel groß. Um "Frame 3 vom Zustand Walk" zu zeichnen, muss man nur die richtige Zelle ausschneiden — genau die 9-Argumente-Form von drawImage() aus Kapitel 2. 

const STATES = {
  Idle: { row: 0, count: 8 },
  Walk: { row: 1, count: 8 },
  Jump: { row: 2, count: 8 },
};

function drawFrame(state, frame, x, y) {
  const def = STATES[state];
  const sx = frame * CELL_W;
  const sy = def.row * CELL_H;
  ctx.drawImage(sheet, sx, sy, CELL_W, CELL_H, x, y, CELL_W, CELL_H);
}

Demo 1 zeigt das in Reinform: von Hand durch die 8 Frames der Walk-Animation klicken. Keine Automatik — nur das Prinzip.

Automatische Wiedergabe: Zeit statt Klicks

Statt zu klicken, berechnet man den Frame aus der verstrichenen Zeit — dieselbe dt-Technik aus Kapitel 1, nur diesmal für die Bildauswahl statt für Bewegung: 

let frame = Math.floor(t * fps) % anzahlFrames;

t ist die Gesamtzeit seit Animationsstart in Sekunden, fps die gewünschte Abspielgeschwindigkeit (Frames pro Sekunde — nicht zu verwechseln mit der Bildrate des Bildschirms). Bei fps=12 und 8 Frames dauert ein kompletter Zyklus 8/12 ≈ 0,67 Sekunden. Genau diese Formel steht (nahezu wortgleich) in drawNinja().

Mehrere Zustände: Loop vs. einmalig

Nicht jede Animation soll sich wiederholen. Idle und Walk laufen endlos — ein Sprung dagegen soll einmal durchlaufen und am letzten Frame (in der Luft) stehen bleiben, bis die Landung eine andere Animation auslöst.

Endlosschleife (Idle/Walk) 
frame = Math.floor(t*fps)
  % count;
Einmalig (Jump) 
frame = Math.min(
  Math.floor(t*fps),
  count - 1);

% count lässt den Frame-Index bei Erreichen des Endes wieder bei 0 anfangen — Math.min(..., count-1) dagegen "klemmt" ihn am letzten gültigen Frame fest. In Ninja Fight entscheidet ein einfaches Set aus Zustandsnamen (loopStates), welche der beiden Formeln gerade gilt.

Bei Demo 3 zwischen Idle/Walk/Jump wechseln — Idle und Walk laufen weiter, Jump bleibt nach einem Durchlauf am letzten Frame stehen.
