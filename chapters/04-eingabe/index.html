Tastatur- & Maus-Eingabe

Der Baustein, der ein bewegliches Rechteck zu etwas macht, das man tatsächlich steuern kann. Das hier aufgebaute keys-Objekt ist wortwörtlich dieselbe Struktur wie GameManager.keys in Ninja Fight.

Das Problem mit rohen Events

keydown und keyup feuern jeweils einmal — beim Drücken bzw. Loslassen. Für "die Figur soll sich bewegen, solange die Taste gehalten wird" reicht das allein nicht: man bräuchte in der Event-Funktion selbst schon eine Bewegung anstoßen, hätte aber keine Kontrolle über das Aufhören, ohne sich selbst Buchhaltung zu bauen.

Demo 1 zeigt das Rohmaterial: jeder Tastendruck erzeugt eine Log-Zeile. Kein Zustand, nur Momentaufnahmen.

Die Lösung: ein Key-State-Objekt

Statt in der Event-Funktion selbst etwas zu bewegen, setzt sie nur ein Flag. Der Game-Loop (aus Kapitel 1) fragt dieses Flag bei jedem Frame ab — dadurch bewegt sich die Figur automatisch, solange die Taste gehalten wird, und hört auf, sobald sie los ist. 

const keys = { left: false, right: false, up: false, down: false };

function keyDown(e) {
  if (e.code === "ArrowLeft") keys.left = true;
  // ...
}
function keyUp(e) {
  if (e.code === "ArrowLeft") keys.left = false;
  // ...
}

// im Loop, jeden Frame:
if (keys.left) x -= SPEED * dt;

Das ist exakt GameManager.keys in Ninja Fight — keyDown()/keyUp() setzen nur Flags, Hero.moveHorizontal() fragt sie jeden Frame ab. Die Eingabe-Erkennung und die Bewegungslogik sind dadurch vollständig getrennt — ein wichtiges Prinzip, das sich durch den Rest des Spiels zieht.

e.key vs. e.code

e.key liefert das tatsächliche Zeichen (abhängig vom Tastaturlayout — auf einer deutschen Tastatur würde Z und Y vertauscht sein). e.code liefert die physische Tastenposition, unabhängig vom Layout — deshalb prüft Ninja Fight durchgehend e.code ("KeyW" statt "w").

Maus-Klicks: Koordinaten umrechnen, dann Trefftest

e.clientX/clientY sind Bildschirmkoordinaten. Um zu wissen, wo der Klick innerhalb des Canvas war, zieht man die Position des Canvas auf der Seite ab (getBoundingClientRect()) — danach ist es nur noch ein normaler Rechteck-Trefftest. Dasselbe Muster erkennt sowohl Klicks auf Menü-Buttons als auch (im späteren Kurs-Projekt) die Auswahl einer Spielfigur per Klick.

Bei Demo 2 mit WASD/Pfeiltasten den Kreis bewegen — er bewegt sich nur, solange eine Taste gehalten wird, und stoppt sofort beim Loslassen.
