Level-Daten & Tile-Rendering

Kapitel 6 hat Plattformen direkt im Code definiert. Das reicht für eine Demo, aber nicht für ein Spiel mit vielen Leveln. Dieses Kapitel trennt "was steht wo" (Daten) von "was bedeutet das" (Code) — exakt wie levels.js und buildLevel() in Ninja Fight.

Das Problem mit hartkodierten Plattformen

ctx.fillRect(20, 60, 150, 10) direkt im Code zu schreiben funktioniert — bis man einen zweiten Level braucht. Dann müsste man den Code kopieren und die Zahlen ändern. Zehn Level später hat man zehn fast identische Code-Blöcke, die sich nur in ein paar Zahlen unterscheiden.

Die Lösung: Level als Daten beschreiben

Statt Code zu schreiben, der eine Plattform erzeugt, schreibt man eine Liste, die beschreibt, was wo steht — reine Daten, keine Logik: 

const LEVEL_1 = [
  { type: "Floor", x: 0,   y: 414 },
  { type: "Floor", x: 40,  y: 414 },
  { type: "Ladder", x: 726, y: 293 },
  { type: "Knives", x: 481, y: 300 },
  // ...
];

Das ist exakt das Format von levels.js in Ninja Fight — { type, x, y }, sonst nichts. Die Bedeutung jedes Typs steckt nicht in den Daten, sondern im Code, der sie verarbeitet.

buildLevel(): Rohdaten nach Bedeutung sortieren

Eine flache Liste reicht der Spiellogik nicht — sie will wissen: "gegen welche Elemente kollidiere ich als Boden?", "welche sind Leitern?", "welche sind Gefahren?". buildLevel() sortiert die Rohdaten genau einmal in diese Kategorien: 

function buildLevel(raw) {
  const platforms = [], ladders = [], hazards = [];
  raw.forEach(el => {
    if (PLATTFORM_TYPEN.has(el.type)) platforms.push(el);
    else if (el.type === "Ladder") ladders.push(el);
    else if (el.type === "Knives") hazards.push(el);
  });
  return { platforms, ladders, hazards };
}

Der Rest des Spiels (Kollision, Kletter-Logik, Gefahren-Prüfung — alle aus den vorigen Kapiteln) arbeitet danach nur noch mit level.platforms, level.ladders usw. und muss die rohen Typnamen nie wieder anfassen.

Derselbe Code, ein anderer Level

Der eigentliche Gewinn: Um einen zweiten Level hinzuzufügen, braucht man keine einzige Zeile am Rendering- oder Kollisions-Code zu ändern — nur eine neue Datenliste zu schreiben und sie stattdessen zu übergeben.

Bei Demo 3 zwischen zwei komplett unterschiedlichen Leveln wechseln — derselbe drawTile()-Aufruf zeichnet beide, nur die Datenliste ändert sich.
