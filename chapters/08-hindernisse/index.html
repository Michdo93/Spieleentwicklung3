KAP·08

Hindernisse & Gefahren

Nicht jedes Level-Element ist eine Plattform zum Draufstehen. Dieses Kapitel baut checkHazards() nach — dieselbe Funktion existiert (fast wortgleich) für Held und Gegner in Ninja Fight.

Überraschung: Wasser ist keine Gefahr

Man könnte erwarten, dass Wasser gefährlich ist — in Ninja Fight ist WaterGround aber eine ganz normale Plattform (Teil der PLATFORM_TYPES-Menge aus Kapitel 7). Man läuft einfach drüber, wie über Boden. Nicht jedes Level-Element, das anders aussieht, muss auch anders funktionieren.

Feuer: Schaden über Zeit, mit Abklingzeit

Feuer ist der interessante Fall: Steht man mitten drin, würde ohne Gegenmaßnahme jeder einzelne Frame Schaden anrichten — bei 60fps wären das 60 Treffer pro Sekunde! Die Lösung: ein invulnTimer, der nach einem Treffer eine kurze Sperrzeit setzt. 

if (invulnTimer <= 0 && berührtFlamme) {
  hp -= 1;
  invulnTimer = 0.6; // 0,6 Sekunden Sperre
}
if (invulnTimer > 0) invulnTimer -= dt;

Das ist exakt der Flame-Teil aus checkHazards() — die Reihenfolge ist wichtig: erst prüfen und ggf. Schaden anrichten, dann den Timer runterzählen (sonst würde der gerade gesetzte Timer im selben Frame schon wieder ablaufen).

Stacheln: dieselbe Technik, höherer Schaden

Stacheln benutzen exakt dieselbe Abklingzeit-Logik wie Feuer — nur mit einem höheren Schadenswert (5 statt 1). Wichtig: In dieser Version verlieren auch Gegner nur Lebenspunkte durch Stacheln, statt sofort zu sterben — eine bewusste Design-Entscheidung, keine Notwendigkeit der Technik selbst.

Feuer 
hp -= 1;
invulnTimer = 0.6;
Stacheln 
hp -= 5;
invulnTimer = 0.6;

Derselbe Mechanismus, unterschiedliche Werte — ein gutes Beispiel dafür, wie sich neue Gefahrentypen mit minimalem neuem Code hinzufügen lassen, sobald das Grundmuster einmal steht.

Mit den Pfeiltasten in die Flamme bzw. auf die Stacheln laufen und beobachten: der Kreis wird orange, während die Abklingzeit läuft — währenddessen richtet weiteres Stehenbleiben keinen zusätzlichen Schaden an.
