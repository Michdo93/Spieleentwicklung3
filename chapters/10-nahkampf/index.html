Nahkampf & Hitboxen

Kapitel 6 hat AABB-Kollision für Landung genutzt — dieselbe Technik erkennt auch Treffer. Dieses Kapitel baut den Angriffs-Teil aus Hero.update() nach.

Die Trefferzone wandert mit der Blickrichtung

Ein Schlag trifft nicht überall — nur in einem kleinen Bereich vor der Figur. Weil facing (aus Kapitel 2) schon bekannt ist, lässt sich die Zone einfach je nach Blickrichtung links oder rechts der Figur platzieren: 

const hitBox = rectOf(
  x + (facing > 0 ? 0 : -range),
  y - 40,
  range, 30
);

Bei facing = 1 (rechts) beginnt die Zone direkt bei x und reicht nach rechts; bei facing = -1 beginnt sie range Pixel links von x. Eine einzige Formel für beide Richtungen.

Ein Treffer pro Angriff — nicht einer pro Frame

Eine Angriffsanimation dauert einige Zehntelsekunden, also mehrere Frames. Ohne Sperre würde jeder einzelne Frame, in dem sich Trefferzone und Gegner überlappen, erneut Schaden anrichten. Die Lösung ist ein einfaches Flag: 

if (attackTimer > 0 && !attackHitDone) {
  if (overlaps(hitBox, gegner.box)) {
    gegner.takeDamage(schaden);
    attackHitDone = true; // ab jetzt gesperrt, bis der nächste Angriff startet
  }
}

attackHitDone wird erst wieder auf false gesetzt, wenn eine neue Angriffsanimation beginnt — Demo 2 zeigt den Unterschied direkt nebeneinander: ohne Sperre zählt jeder Frame, mit Sperre genau einer pro Angriff.

Unterschiedliche Reichweite und Schaden je Angriffsart

Schlag, Tritt und Schwert benutzen exakt dieselbe Trefferzonen- Logik — nur mit unterschiedlichen Werten:

AngriffReichweiteSchaden
Schlag (Hit)30px1
Tritt (Kick)34px2
Schwert (Sword)46px10

Genau diese Tabelle steht als DAMAGE-Konstante in entities.js — Reichweite und Schaden sind bewusst gekoppelt: eine größere Waffe trifft weiter und härter.

Bei Demo 3 mit den drei Angriffsarten auf den Gegner einwirken — die HP-Anzeige zeigt sofort, wie unterschiedlich stark jede Angriffsart wirkt.
