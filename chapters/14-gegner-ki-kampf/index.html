Gegner-KI: Kampf & Gegnertypen

Bewegung (Kapitel 13) allein macht noch keinen Gegner gefährlich. Dieses Kapitel baut die Angriffsentscheidung aus Enemy.update() nach: je nach Abstand ein anderer Angriff, je nach Gegnertyp überhaupt erst verfügbar.

Angriffsauswahl nach Abstand

Ein Gegner entscheidet jeden Frame neu, was er tun soll — abhängig vom Abstand zum Ziel und von seinen eigenen Fähigkeiten: 

const dist = Math.hypot(hero.x - x, hero.y - y);

if (dist < 40) {
  // Nahkampf: Schlag oder Tritt
} else if (dist < 260 && hasShuriken) {
  // Shuriken werfen
} else if (dist < 60 && hasSword) {
  // Schwerthieb
}

Die Reihenfolge der Prüfungen ist wichtig: Nahkampf hat Vorrang vor Fernkampf, weil er (in Ninja Fight) den geringsten Abstand voraussetzt — ein Gegner, der nah genug für einen Schlag ist, würde sonst unnötig ein Shuriken werfen.

Vier Gegnertypen, vier Fähigkeitsprofile

Nicht jeder Gegner kann alles. In Ninja Fight sind Fähigkeiten und Lebenspunkte an den Typ gekoppelt:

TypHPShurikenSchwert
Blue10——
Green20✓—
Red30—✓
White50✓✓

Schlagen und Treten kann jeder — Shuriken und Schwert sind exklusive Spezialfähigkeiten. Ein Gegner ohne hasShuriken erreicht die entsprechende if-Bedingung im Entscheidungsbaum oben schlicht nie.

Friendly Fire: ein Angriff kennt keine Teams

Ein wichtiges Detail aus Kapitel 11: ein Projektil trifft jeden außer seinem eigenen Werfer. Das bedeutet, ein Shuriken, das ein Gegner in Richtung des Helden wirft, kann versehentlich einen anderen Gegner treffen, der zufällig im Weg steht — es gibt keinen Sonderfall-Code, der "Gegner gegen Gegner" ausschließt.

Bei Demo 3 werfen und beobachten: das Shuriken ist eigentlich für den Helden gedacht, trifft aber den zufällig dazwischenstehenden anderen Gegner.
